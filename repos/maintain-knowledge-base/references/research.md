# 社区方法调研摘要

调研日期：2026-08-14。

本 Skill 采用混合方法，不要求用户完整照搬任一 PKM 流派。

## 吸收的原则

### PARA 与 CODE

吸收按行动性和生命周期区分项目、长期领域、资源和归档，以及捕获、组织、提炼和使用的处理流。没有采用四个顶层文件夹作为全部知识模型，因为结构化事实和实体关系需要独立登记。

来源：https://fortelabs.com/blog/progressive-summarization-a-practical-technique-for-designing-discoverable-notes/

### Zettelkasten

吸收唯一身份、适度原子化、明确链接、结构入口和“必须加工来源而非只收藏”的原则。没有要求资产、会议和项目记录全部原子化。

来源：https://zettelkasten.de/overview/

### Evergreen Notes

吸收概念导向、持续修订和有语义连接，使知识能够跨项目累积。避免把每条来源笔记永久隔离在书籍或项目之下。

来源：https://notes.andymatuschak.org/About_these_notes

### Johnny.Decimal

吸收稳定、低歧义、易于口头和机器引用的地址思想。没有强制所有目录采用固定两位数字容量。

来源：https://johnnydecimal.com/documentation/areas-and-categories

### FAIR

吸收唯一标识、丰富元数据、可检索索引、合格关系和详细来源。将其缩减为适合本地文件知识库的轻量实现。

来源：https://www.go-fair.org/fair-principles/

### Diátaxis

吸收教程、操作指南、参考和解释应满足不同需求的原则，用于避免协议、参数表和概念解释混写。

来源：https://diataxis.fr/start-here/

## 当前社区与研究提示

- 检索习惯会反过来塑造知识库结构，因此架构应从高频问题出发，而不是从漂亮目录出发。
- 混合 PARA、Zettelkasten 和稳定编号比纯粹套用单一方法更适合同时管理项目、事实和通用知识。
- 复杂元数据、过度原子化、频繁重构和只收藏不提炼会使维护成本失控。
- 本地纯文本有利于迁移、全文检索、版本控制和 Agent 读取；专用软件功能应当作为增强层。
