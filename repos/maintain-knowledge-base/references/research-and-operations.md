## 1. 共同原则

科研和事务项目都使用统一项目 ID、中央实体登记和关系表，但项目内部模板不同。项目是上下文容器，不是所有长期事实的所有者。

共同要求：

- 项目入口解释目标、范围、状态、负责人角色和关键对象；
- 稳定对象通过实体 ID 引用；
- 重要决定使用独立决策记录；
- 产物、来源和结论之间建立可追溯关系；
- 完成后保留摘要、最终状态和可复用成果。

## 2. 科研项目

科研 `PROJECT.md` 至少包含：

- 研究问题或目标；
- 背景和范围；
- 假设或待验证主张；
- 相关设备、软件、样本、数据集、方法和标准 ID；
- 实验和分析入口；
- 当前结果与限制；
- 关键决策；
- 可晋升的通用知识候选；
- 主要报告和来源。

推荐流向：

```text
研究问题
  → 方法/协议
  → 实验与运行
  → 原始数据
  → 处理数据与分析
  → 结果和限制
  → 报告
  → 可复用知识候选
```

不要只保存最终结论。为可重复性保留输入、参数、软件环境、设备、样本、命令或工作流、输出、质量检查和异常。

## 3. 实验、数据和来源

### 实验

为需要独立引用或多次运行的实验分配 `EXP-*` ID。记录目的、输入、协议、参数、环境、执行者角色、日期、输出、异常和结论边界。

### 数据

大型数据可外置。知识库至少登记：

- 数据集 ID 和稳定路径；
- 获取或生成方式；
- 设备、样本、实验和软件关系；
- 文件指纹或版本；
- 数据字典、单位和格式；
- 访问权限和敏感性；
- 质量控制和已知限制。

### 论文和标准

来源记录保存书目信息、稳定标识、文件路径和访问日期。知识条目只保存经过理解和重写的主张，并链接来源。直接摘录要明确标记，避免失去语境。

## 4. 事务项目

事务项目可以覆盖采购、合作、申请、会议筹备、制度更新、交付和行政协调。`PROJECT.md` 至少包含：

- 目标和完成标准；
- 范围和不包含事项；
- 利益相关组织或角色；
- 关键日期与长期承诺；
- 相关材料和来源；
- 决策和审批；
- 当前状态、阻塞项和最终结果；
- 后续义务与归档条件。

知识库不是密码管理器，也不应无必要保存身份证号、银行信息等敏感个人数据。事务资料只保存实现检索和审计所需的最少信息。

会议流水、即时聊天和待办并不自动成为长期知识。仅沉淀决定、责任、理由、交付物、长期约束和可复用流程。

## 5. 跨项目知识流动

科研项目可产生方法、协议、排障经验和概念解释；事务项目可产生标准流程、模板、供应商经验和政策解释。两类内容都先保留在项目中，再按验证程度晋升。

晋升后的通用知识需要：

- 独立于原项目的标题和适用范围；
- 原项目和来源关系；
- 限制、例外和失效条件；
- 明确状态，例如 `candidate` 或 `validated`；
- 被后续项目引用时继续修订，而不是复制新版本。

## 6. 典型查询

| 问题 | 数据入口 |
|---|---|
| 我有多少个可用探头 | 实体表按 `type/subtype/status` 过滤 |
| 某探头参加过哪些实验 | 实体 ID → 关系表 → 实验和项目 |
| 某数据集如何生成 | 数据集 → `derived_from/produced_by` → 实验、设备、协议 |
| 哪些项目使用某方法 | 方法 ID → 关系表中的 `applies` |
| 某结论可信度如何 | 知识条目 → 原项目 → 实验/数据 → 来源与限制 |
| 某采购为什么选择该供应商 | 事务项目 → 决策记录 → 选项、证据和审批 |
| 当前有哪些长期义务 | 活动事务项目 → 决策与交付记录 |
