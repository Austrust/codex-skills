# 备份、恢复与迁移

## 何时备份

- 结构操作（审计修复、移动/合并、改 schema/词表/模板、迁移）开始前；
- 恢复备份前先备份当前状态，避免恢复时丢掉用户的新改动；
- 用户要求备份，或大范围归档前。

只读审计不要求备份。

## 最小备份

1. 知识库在 Git 内：先看 `git status --short`，确认未提交改动的归属；在分支或独立副本上操作。
2. 不在 Git 内：把 `catalog/` 与受影响的条目/项目目录复制到库外备份位置（`$env:TEMP` 或用户指定目录），目录名带时间戳；备份不留在知识库内。
3. 记录备份路径、时间、覆盖范围与将要执行的操作。

## 执行与验收

- 结构操作先预演：列出将改动的文件、ID、关系和导航入口，向用户说明后再执行。
- 操作后运行 `audit_kb.py`，并记录 `entities`/`projects`/`relations` 行数变化。
- 复核入口：受影响项目的 `PROJECT.md`、条目链接与导航（导航交 `research-readme-index`）。
- 审计有 error 时先修复再继续；warning 逐条判断，不用「跑过就算」代替语义检查。

## 恢复

1. 只读对比备份与现状（`git diff` 或文件对比），列出差异；
2. 说明将覆盖哪些文件、会丢失哪些新改动，得到用户确认后再覆盖；
3. 恢复后重新审计并复核入口；
4. 不静默丢弃用户新改动；不恢复时就地删除当前状态。

## 迁移

1. 建立旧路径 → 新路径映射；
2. 先只读审计和迁移计划，小范围样本验证；
3. 保留可恢复副本；
4. 更新 `canonical_path`、`relations.csv` 中的路径/引用与导航（导航交 `research-readme-index`）；
5. 迁移后重新审计。

默认归档而非删除：归档记录保留 ID、原路径或重定向、归档时间、原因和替代对象；不复用已分配 ID。未经用户明确授权，不做批量删除或不可逆重命名。
