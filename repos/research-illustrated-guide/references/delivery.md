# 图源与交付实现

## 文件组织

遵循已有项目结构。新资料包可包含 `guide.md`、`guide.html`、`figures/`、参考文献和图源索引。原文保存在项目现有文献区或包内来源目录，正文使用可用链接。修改已有成果时保留需要的历史版本。

来源记录至少包括来源标识、题名、作者/机构、年份、URL/DOI、访问日期、本地文件和阅读依据（全文、相关页、摘要、官方页面等）。学术来源可附 BibTeX；网页来源记录页面标题与机构，不编造期刊字段。重定向或下载失败须检查实际文件，避免把错误页当原文。

图源索引记录正文图号、图片路径、来源标识、原图号、PDF 页码或网页位置，以及裁剪/重绘说明。复杂裁图可额外记录裁剪坐标和原文件校验值。无需给每幅简单示意附加无关字段。

## 图片检查

核读原图及相邻说明后编写中文读图提示。检查轴与单位、颜色、实验阶段、样本对象、面板次序及数据类型。裁图保留坐标和图例，避免夹入半行正文或截断图注。组合图保留面板对应关系。特别注意综述转载的图片实际来源。

离线 HTML 应嵌入图像，或完整打包所有本地资源；避免依赖外网脚本、字体或图片。图像放大后仍应可读。引用网页链接可在联网时访问，离线不影响正文和图片阅读。

## 阅读版生成器

`scripts/build_reader.mjs` 使用 Node.js 和 `marked`。优先通过环境提供的依赖发现工具寻找运行时；Codex 桌面可用 `load_workspace_dependencies`，其他环境使用已安装运行时。脚本不安装依赖，不联网下载图片。

```text
node <skill>/scripts/build_reader.mjs <guide.md> <guide.html> --modules <node_modules目录>
```

`--modules` 可省略：脚本会尝试正常模块解析；也可通过 `CODEX_NODE_MODULES` 指定模块目录。所有 Markdown 图片须为本地 PNG/JPEG/GIF/WebP/SVG。外部图片先取得可用本地文件并核对来源，或改为普通来源链接。输出目录必须存在；输入输出必须不同。

脚本从一级标题提取标题，为二级标题建立目录，将本地图片嵌入 HTML，并提供图片放大与原始尺寸切换。它会拒绝缺失图片和外部图片，避免生成假离线成果。它转义原始 HTML，仅支持普通 Markdown；复杂公式需使用经过检查的本地数学渲染方案，或在说明充分时使用 Unicode 公式。不要把复杂 LaTeX 公式直接当作已渲染内容交付。

## 最终验证

检查参考编号、图片路径、图源索引和正文一致。用本地浏览器或渲染工具实际打开阅读版，检查中文、长表格、窄屏、纵向图、图片放大及链接。确认无图片缺失、布局溢出或标签裁断。目录确认后的写作和视觉修正自主完成，达到用户指定终点后交付。
